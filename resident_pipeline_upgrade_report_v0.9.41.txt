Resident Pipeline Upgrade/Fix Report v0.9.41
============================================

Scope
-----
This version upgrades Option 22 into a guided abundance/population-model fitting wizard while preserving the working v0.9.40 standalone architecture and the existing model-storage path used by Options 23-28.

What changed in Option 22
-------------------------
Option 22 now prints:
- a clear title: Select and fit abundance/population model;
- a data-readiness snapshot before fitting;
- the recommendation carried forward from Option 21;
- a compact model-status overview;
- grouped selectable model families;
- implementation-status labels;
- comparable-likelihood group labels;
- an explicit statement that Cormack-Jolly-Seber is not an abundance model and is not selectable here;
- a selected-model teaching card before fitting;
- post-fit storage confirmation and next-step guidance.

Model status policy
-------------------
The interface now distinguishes:
- fully functional descriptive outputs: observed_only and chao1_chao2;
- current direct likelihood: closed_M0;
- diagnostic/simplified outputs: closed_Mt, closed_Mb, closed_Mh_mixture, huggins_M0, huggins_Mt;
- diagnostic outputs requiring temporal structure: robust_design_closed_primary and robust_design_huggins_primary;
- diagnostic open-population summaries: jolly_seber and POPAN_like.

CJS policy
----------
Cormack-Jolly-Seber is explicitly excluded from Option 22 because it is not an abundance model. It estimates apparent survival/persistence and detection for already observed/marked individuals.

Preserved behavior
------------------
The fitting/storage backend remains intact. Option 22 still stores fitted or diagnostic results in:
- analysis$abundance_fit
- analysis$fitted_model
- analysis$model_fit
- analysis$model_results

Option 23 continues to retrieve the stored fit.

Regression caught during development
------------------------------------
The first v0.9.41 implementation merged new status metadata with the old detail table without resolving duplicate `implementation_status` columns. This prevented implementation-status labels from displaying. The bug was caught by Test 11 before delivery and fixed by explicitly coalescing the metadata column.

Remaining scientific limitations
--------------------------------
v0.9.41 improves the Option 22 interface and safety labelling. It does not yet implement full Program MARK-equivalent closed-capture likelihoods, full Huggins conditional likelihoods, full robust-design likelihoods, full Jolly-Seber likelihood, or full POPAN likelihood. The interface now labels current diagnostic outputs honestly so they are not mistaken for final comparable likelihood inference.
